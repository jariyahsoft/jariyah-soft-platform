# 18. Public API

## API Specification

**Base URL**: `https://api.jariyah.dev/v1`
**Authentication**: API Key (`X-API-Key` header)

### 18.1 Software API
* `GET /software` - List software (Query: `category`, `tag`, `page`, `limit`)
* `GET /software/{id}` - Get software details
* `GET /software/trending` - Get trending software
* `GET /software/{id}/reviews` - Get software reviews

### 18.2 Article API
* `GET /articles` - List articles (Query: `category`, `author`, `page`, `limit`)
* `GET /articles/{id}` - Get article details

### 18.3 Developer API
* `GET /developers/{id}` - Get developer profile
* `GET /developers/{id}/software` - Get software by developer

### 18.4 API Key Management
* `POST /api-keys` - Generate new API Key (Requires User Auth)
* `DELETE /api-keys/{id}` - Revoke API Key

### Rate Limiting
* Anonymous: 100 req/hour
* Authenticated: 1,000 req/hour
* Premium Developer: 10,000 req/hour

# 23. Firestore Collections Schema

ระบบใช้ Cloud Firestore เป็นฐานข้อมูลหลัก โดยมี Schema เบื้องต้นดังนี้:

## 1. `users` (สมาชิกทั่วไป)
* `uid` (String, PK)
* `displayName` (String)
* `email` (String)
* `photoURL` (String)
* `roles` (Array[String]) - e.g., ['member', 'developer', 'moderator', 'admin']
* `createdAt` (Timestamp)
* `lastLoginAt` (Timestamp)
* `status` (String) - 'active', 'suspended'

## 2. `developers` (โปรไฟล์นักพัฒนา - Subcollection หรือแยก Collection)
* `developerId` (String, PK - ตรงกับ uid)
* `bio` (String)
* `skills` (Array[String])
* `githubUrl` (String)
* `websiteUrl` (String)
* `reputationScore` (Number)
* `badges` (Array[String])
* `isVerified` (Boolean)

## 3. `software` (ข้อมูลซอฟต์แวร์)
* `id` (String, PK)
* `name` (String)
* `developerId` (String, FK)
* `description` (String)
* `categoryId` (String)
* `tags` (Array[String])
* `logoUrl` (String)
* `downloadUrls` (Map) - { 'windows': 'url', 'github': 'url' }
* `status` (String) - 'draft', 'submitted', 'approved', 'rejected'
* `stats` (Map) - { 'downloads': 0, 'rating': 0.0, 'views': 0 }
* `createdAt` (Timestamp)
* `updatedAt` (Timestamp)

## 4. `articles` (บทความความรู้)
* `id` (String, PK)
* `title` (String)
* `content` (String - Markdown/HTML)
* `authorId` (String, FK)
* `categoryId` (String)
* `status` (String) - 'draft', 'published'
* `viewCount` (Number)
* `publishedAt` (Timestamp)

## 5. `reviews` (รีวิวซอฟต์แวร์)
* `id` (String, PK)
* `softwareId` (String, FK)
* `userId` (String, FK)
* `rating` (Number) - 1 to 5
* `comment` (String)
* `createdAt` (Timestamp)

*(Collection อื่นๆ ใช้รูปแบบโครงสร้างที่คล้ายคลึงกัน โดยเน้นการทำ Denormalization สำหรับข้อมูลที่มีการ Query บ่อย เช่น ชื่อผู้เขียนใน Article)*

# 24. Security Requirements

* HTTPS บังคับใช้ทุกช่องทาง
* Rate Limiting & DDos Protection (ผ่าน Firebase Hosting / Cloudflare)
* Audit Logging สำหรับ Admin Actions ทุกประเภท
* Input Validation และ Sanitization ป้องกัน XSS
* Encryption at Rest และ in Transit (Firebase Default)

## Firebase Security Rules (High-Level)
* **Users**: อ่านโปรไฟล์ผู้อื่นได้ (Public info) เขียน/แก้ไข ได้เฉพาะ UID ของตัวเองเท่านั้น
* **Software/Articles**:
  * `read`: ถ้าสถานะเป็น 'approved' ทุกคนอ่านได้
  * `write`: เฉพาะ Owner แก้ไขได้ (เมื่อสถานะเป็น draft/submitted) หรือ Admin/Moderator แก้ไขได้
* **Reviews**:
  * `read`: ทุกคนอ่านได้
  * `write`: สมาชิกที่ Login แล้วเขียนได้, แก้ไขได้เฉพาะของตัวเอง (UID ตรงกัน)
* **Admin/Moderator Data**: ตรวจสอบ Role จาก Custom Claims (`request.auth.token.role == 'admin'`)

# 26. User Stories & Detailed Acceptance Criteria

## Guest

### US-001 ดูรายการซอฟต์แวร์
* **As a** Guest
* **I want to** browse software
* **So that** I can find software that meets my needs.

**Acceptance Criteria**
* [ ] ระบบแสดงรายการซอฟต์แวร์ที่สถานะ 'approved' เท่านั้น
* [ ] มี Pagination หรือ Infinite Scroll (โหลดทีละ 20 รายการ)
* [ ] ค้นหาและกรองตามหมวดหมู่ได้ภายใน < 1 วินาที
* [ ] ถ้าไม่พบข้อมูล ให้แสดง Empty State พร้อมคำแนะนำ

### US-002 ดาวน์โหลดซอฟต์แวร์
* **As a** Guest
* **I want to** download software
* **So that** I can use it immediately.

**Acceptance Criteria**
* [ ] ผู้ใช้คลิกปุ่มดาวน์โหลดได้โดยไม่ต้องสมัครสมาชิก
* [ ] ระบบบันทึกสถิติ Download +1 ใน Background โดยไม่รอผลกระทบต่อ UI
* [ ] Redirect ไปยัง URL ปลายทางอย่างถูกต้อง
* [ ] แจ้งเตือนข้อผิดพลาด (เช่น Broken Link) หากดาวน์โหลดไม่ได้

## Member

### US-003 สมัครสมาชิกและจัดการโปรไฟล์
* **As a** Member
* **I want to** register and manage my profile
* **So that** I can review software and participate in the community.

**Acceptance Criteria**
* [ ] สมัครสมาชิกผ่าน Email/Password, Google, GitHub ได้
* [ ] ต้องยืนยัน Email Verification ก่อนใช้งานฟังก์ชัน Comment/Review
* [ ] ผู้ใช้สามารถเปลี่ยนชื่อ Display Name และรูปโปรไฟล์ได้
* [ ] ผู้ใช้สามารถลบบัญชีตัวเองได้ (Account Deletion / PDPA)

## Developer

### US-101 ส่งซอฟต์แวร์เข้าระบบ
* **As a** Developer
* **I want to** submit my software
* **So that** users can discover and download it.

**Acceptance Criteria**
* [ ] ฟอร์มบังคับกรอก: ชื่อ, หมวดหมู่, รูป Logo, รายละเอียดแบบยาว, และ Link ดาวน์โหลด

### US-201 อนุมัติซอฟต์แวร์

* **I want to** review submitted software
* **So that** I can ensure quality and compliance.

**Acceptance Criteria**

# 29. Error Handling

## File Upload
* ขนาดสูงสุด: Logo 5 MB, Screenshot 10 MB, PDF 50 MB
* รูปแบบไฟล์ไม่ถูกต้อง: แจ้งเตือน "รองรับเฉพาะไฟล์ .JPG, .PNG"
* Quota Exceeded: แจ้งเตือนให้รอ หรือติดต่อ Admin

## External Integration
* GitHub API / Social Login Timeout: Retry แบบ Exponential Backoff (สูงสุด 3 ครั้ง) หากยังไม่ได้ให้แสดงข้อความ "ระบบเชื่อมต่อมีปัญหา กรุณาลองใหม่ภายหลัง"
* Broken Download Link: ซ่อนปุ่มโหลดอัตโนมัติ (แจ้ง Admin & Developer)

## System & Database Errors
* Firestore Permission Denied: เตะผู้ใช้กลับหน้า Login หรือแสดงหน้า 403 Forbidden
* Network Offline (PWA): แสดงแถบแบนเนอร์ "คุณกำลังใช้งานแบบออฟไลน์" โหลดข้อมูลจาก Cache
* Concurrent Editing: ใช้ Optimistic UI, หากมีการชนกัน (Conflict) ให้เด้งเตือน "ข้อมูลถูกเปลี่ยนแปลงโดยผู้ใช้อื่น กรุณารีเฟรชหน้า"

# 30. Search Requirements & Implementation

## เทคโนโลยี (Search Implementation)
* เลือกใช้ **Typesense Cloud** หรือ **Algolia** สำหรับทำ Full-Text Search เนื่องจาก Firestore ไม่รองรับ Full-Text Search โดยตรง
* ใช้ Firebase Cloud Functions เป็นตัว Sync ข้อมูล (Firestore Triggers `onWrite`) ไปยัง Typesense

## ความสามารถการค้นหา
* **Full Text Search**: ค้นหาจาก Title, Description, Tags
* **Synonym Search**: ตั้งค่าคำพ้องความหมาย (เช่น "โปรแกรมพิมพ์งาน" = "Word Processing")
* **Language Support**: รองรับการตัดคำภาษาไทย (Thai Tokenizer) และอังกฤษ
* **Fuzzy Search**: ค้นหาเจอแม้พิมพ์ผิดพลาดเล็กน้อย (Typo Tolerance)
* **Faceted Search**: กรองตาม Categories, Platforms (Windows, Mac, Web), License

## Search Ranking Algorithm
1. **Relevance**: ตรงกับ Keyword แค่ไหน (Title น้ำหนักมากที่สุด)
2. **Popularity**: ยอด Download + View
3. **Recency**: วันที่อัปเดตล่าสุด
4. **Rating**: คะแนนรีวิวเฉลี่ย

# 39. Data Migration & Seeding Strategy

## Initial Seeding (ข้อมูลเริ่มต้น)
เพื่อให้ระบบมีข้อมูลตั้งต้นและไม่ว่างเปล่าตอน Go-Live:
1. **Master Data**: Seed ข้อมูล `software_categories`, `article_categories`, `badges_list` เข้า Firestore ผ่าน Admin Script
2. **Initial Content**: แอดมินสร้าง "Software แนะนำ" เริ่มต้น จำนวน 10-20 ตัว (โดยขอความร่วมมือจากนักพัฒนา) และสร้าง "บทความ" ตั้งต้น 5-10 บทความ
3. **Dummy Data (เฉพาะ Environment Dev/Staging)**: ใช้ Faker.js สร้างผู้ใช้, ซอฟต์แวร์, และรีวิวเทียม เพื่อใช้ในการทดสอบ Performance และ Pagination

## Database Migration Script
* เขียน Node.js Script (CLI) เพื่อใช้ย้ายหรืออัปเดต Schema ในอนาคต
* บันทึกสถานะ Migration ใน Collection `system_migrations` เพื่อป้องกันรันซ้ำ
